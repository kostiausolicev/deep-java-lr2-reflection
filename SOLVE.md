# Решение лабораторной работы № 2

## Общая идея

Класс `Generator` создаёт случайное значение по переданному объекту `Class<?>`:

```java
Generator generator = new Generator();
Object value = generator.generateValueOfType(String.class);
```

Генерация выполняется в зависимости от категории запрошенного типа. Для простых типов используются методы `Random`, а массивы и пользовательские объекты создаются с помощью Reflection API.

## Поддерживаемые типы

### Примитивные типы и обёртки

Поддерживаются следующие пары:

- `int` и `Integer`;
- `long` и `Long`;
- `float` и `Float`;
- `double` и `Double`;
- `char` и `Character`;
- `boolean` и `Boolean`;
- `short` и `Short`;
- `byte` и `Byte`.

При запросе примитивного типа метод возвращает соответствующее значение в обёртке, поскольку возвращаемый тип метода — `Object`.

### Строки

Генерируется непустая строка длиной от 5 до 19 символов. Строка состоит из случайных строчных латинских букв от `a` до `z`.

Ограниченный диапазон длины не позволяет случайно создать слишком большую строку и делает результат удобным для проверки.

### Перечисления

Для перечисления через `Class.getEnumConstants()` получается массив всех его констант. Из массива случайно выбирается одно значение.

### Массивы

Тип элемента определяется через `Class.getComponentType()`. Массив длиной от 1 до 4 элементов создаётся вызовом:

```java
Array.newInstance(componentType, length)
```

Использование `Array.newInstance`, а не `new Object[]`, сохраняет настоящий тип массива. Например, запросы `int[].class` и `String[].class` возвращают соответственно `int[]` и `String[]`.

Каждый элемент массива рекурсивно создаётся тем же генератором и записывается через `Array.set()`.

### Списки

При прямом запросе `List.class` создаётся непустой `ArrayList<String>` размером от 1 до 4 элементов.

Тип элементов выбран явно, потому что при передаче только `List.class` информация о generic-параметре отсутствует из-за стирания типов. Поэтому генератор не может определить, ожидался `List<String>`, `List<Integer>` или другой список.

Если список является параметром конструктора, например `List<Product>`, генератор получает тип через `Constructor.getGenericParameterTypes()`. Объект `ParameterizedType` позволяет извлечь `Product` и создать список именно с такими элементами.

### Отображения

При прямом запросе `Map.class` создаётся непустой `HashMap<String, Integer>` размером от 1 до 4 пар.

Как и для `List.class`, типы ключей и значений нельзя восстановить из одного объекта `Class<?>`, поэтому для прямого запроса выбраны фиксированные типы `String` и `Integer`.

Для параметризованного параметра конструктора, например `Map<String, Product>`, тип ключа и тип значения извлекаются из `ParameterizedType`, после чего значения генерируются рекурсивно.

## Пользовательские классы

Для пользовательского класса генератор получает все объявленные конструкторы через:

```java
clazz.getDeclaredConstructors()
```

После выбора конструктора генератор получает типы его параметров, рекурсивно создаёт аргументы и вызывает `Constructor.newInstance(arguments)`.

Использование `getGenericParameterTypes()`, а не только `getParameterTypes()`, необходимо для сохранения информации о параметрах `List<T>` и `Map<K, V>`.

## Назначение аннотации `@Generatable`

Аннотация `@Generatable` применяется к конструкторам:

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.CONSTRUCTOR)
public @interface Generatable {
}
```

`RetentionPolicy.RUNTIME` делает аннотацию доступной через Reflection API во время выполнения программы. Ограничение `ElementType.CONSTRUCTOR` не позволяет случайно применить её к классу, полю или методу.

В решении принята следующая семантика:

1. Если ровно один конструктор отмечен `@Generatable`, генератор обязательно выбирает его.
2. Если отмеченных конструкторов нет, генератор случайно выбирает один из доступных конструкторов.
3. Если аннотацией отмечено больше одного конструктора, генерация завершается исключением `IllegalStateException`.

Пример:

```java
public class Product {
    private final String name;
    private final double price;

    @Generatable
    public Product(String name, double price) {
        this.name = name;
        this.price = price;
    }

    public Product(String name) {
        this(name, 0.0);
    }
}
```

В этом случае генератор всегда использует конструктор с двумя параметрами. Таким образом, аннотация влияет на реальную логику программы и позволяет автору класса явно указать предпочтительный способ создания объекта.

## Интерфейсы и абстрактные классы

Интерфейс или абстрактный класс невозможно создать напрямую. Кроме того, стандартный Reflection API не предоставляет универсального метода, возвращающего все реализации интерфейса в classpath.

Поэтому в решении используется явный реестр допустимых реализаций:

```java
Generator generator = new Generator()
        .registerImplementations(
                Shape.class,
                Rectangle.class,
                Triangle.class
        );

Shape shape = (Shape) generator.generateValueOfType(Shape.class);
```

При запросе `Shape.class` генератор случайно выбирает `Rectangle` или `Triangle`, после чего создаёт выбранный класс обычным способом через его конструктор.

Во время регистрации проверяется, что:

- регистрируемый базовый тип является интерфейсом или абстрактным классом;
- передана хотя бы одна реализация;
- каждая реализация совместима с базовым типом;
- зарегистрированная реализация является конкретным классом.

Если для запрошенного абстрактного типа реализации не зарегистрированы, генератор выбрасывает `IllegalArgumentException` с указанием проблемного типа.

Явная регистрация выбрана вместо автоматического сканирования classpath, потому что она не требует сторонних библиотек и точно определяет, какие реализации разрешено создавать.

## Обработка ошибок

Генератор не использует `null` как результат неудачной генерации запрошенного значения. Для неподдерживаемых `Type`, отсутствующих реализаций абстрактного типа и некорректной регистрации выбрасываются исключения с описанием причины.

Методы Reflection API могут выбросить `InvocationTargetException`, `InstantiationException` и `IllegalAccessException`. Эти исключения объявлены в сигнатуре `generateValueOfType`, чтобы вызывающий код мог обработать причину неудачного создания объекта.

Вспомогательные методы могут возвращать `null` только как внутренний признак того, что переданный класс не относится к обрабатываемой ими категории. Этот `null` не возвращается пользователю как результат ошибки.

## Тестирование

JUnit-тесты проверяют свойства результата, а не конкретные случайные значения. Покрыты следующие сценарии:

- все поддерживаемые примитивные типы и их обёртки;
- формат и длина строки;
- принадлежность результата набору констант перечисления;
- настоящий runtime-тип и размер примитивного массива;
- настоящий runtime-тип и содержимое массива ссылочного типа;
- непустой `List<String>`;
- непустой `Map<String, Integer>`;
- генерация зарегистрированной реализации интерфейса;
- генерация зарегистрированной реализации абстрактного класса.

Запуск тестов:

```bash
./gradlew test
```

## Принятые ограничения

- При прямом запросе `List.class` используются элементы типа `String`.
- При прямом запросе `Map.class` используются ключи типа `String` и значения типа `Integer`.
- Размер массивов и коллекций находится в диапазоне от 1 до 4.
- Строки состоят только из строчных латинских букв.
- Для интерфейсов и абстрактных классов требуется предварительная регистрация реализаций.
- Поддерживаются параметризованные типы `List<T>` и `Map<K, V>` в параметрах конструкторов; произвольные generic-типы не поддерживаются.
- Автоматическое сканирование classpath в поисках реализаций не выполняется.
